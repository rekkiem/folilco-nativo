# Notas sobre vulnerabilidades npm

## Estado actual: 5 moderate (aceptables para producción)

### postcss < 8.5.10 (GHSA-qx2v-qp2m-jg93)
- **Afectado:** `node_modules/next/node_modules/postcss` (uso interno de Next.js)
- **Riesgo real:** Bajo. El XSS ocurre solo si PostCSS procesa CSS con input no confiable.
  En este proyecto, PostCSS solo procesa archivos `.css` estáticos del desarrollador.
- **Fix disponible:** `npm audit fix --force` → instala next@9.3.3 ❌ (inaceptable)
- **Mitigación:** Override en package.json fuerza `postcss ^8.5.10` en el scope del proyecto.
  La versión interna de Next.js no puede sobreescribirse sin romper Next.js.

### uuid < 14.0.0 (GHSA-w5hq-g745-h8pq)
- **Afectado:** `node_modules/gaxios/node_modules/uuid` y `node_modules/mercadopago/node_modules/uuid`
- **Riesgo real:** Bajo. El bug solo afecta `v3/v5/v6` cuando se pasa un buffer manualmente.
  El SDK de MercadoPago usa UUID para generar IDs internos, no con buffers externos.
- **Fix disponible:** `npm audit fix --force` → instala mercadopago@0.5.0 ❌ (inaceptable)
- **Mitigación:** Override en package.json. Si npm no aplica el override al scope anidado,
  es porque `mercadopago` y `gaxios` pinnan su propia versión de uuid en su `package.json`.

## Decisión arquitectural
Estas 5 vulnerabilidades **moderate** son en dependencias de terceros (Next.js y MercadoPago SDK)
que no podemos actualizar sin romper la aplicación. Son aceptadas y documentadas.

Si en el futuro se publican versiones de `next` o `mercadopago` sin estas dependencias
vulnerables, ejecutar `npm update` para obtenerlas.

## Comandos correctos
```bash
# ✅ Correcto - aplica fixes sin breaking changes
npm audit fix

# ❌ NUNCA ejecutar - degrada next a 9.x y mercadopago a 0.5.0
npm audit fix --force
```
